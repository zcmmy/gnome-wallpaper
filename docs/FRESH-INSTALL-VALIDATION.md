# 全新安装验收

本轮在 Debian 13、GNOME 48 Wayland、x86_64 的实际桌面进行。
此前的临时安装、隐藏工作区测试和桌面升级迁移，不能替代本轮首次使用验收。

## 基线与边界

- 保留用户 assets、壁纸和静态图片，并逐文件记录哈希。
- 停用并删除已安装壁纸插件，清空本插件 GSettings、管理图库、缓存及恢复/迁移状态。
- 删除相关工作区的全部 build 目录、旧 dist 和隔离构建环境中的项目产物；保留作为第一轮输入的待测安装包、依赖源码和已配置的系统工具链。历史备份不作为安装或构建输入。
- 不清空其他 GNOME 扩展配置，不重启或注销桌面。当前 Shell 的模块缓存通过单独测试过的显式会话入口替换，因此这不是新登录会话测试。
- 两轮分别由用户通过插件设置界面的文件选择器导入本地资源，不用脚本预填图库或恢复配置。

已完成：目标插件、旧配置和全部旧构建目录不存在时，仅使用保存的完整 ZIP 和安装器安装。安装器返回无旧版本回滚副本；首次启用前无管理图库与用户配置。

发现并修复：尚未选择壁纸时误报“所选壁纸不存在”。首次启动现在保持无错误的静态待配置状态；首页增加 assets 与壁纸导入入口，准备完成后隐藏引导。真实的失效选择仍报告错误。

## 第二轮：源码从零构建并安装

已完成：再次删除第一轮安装的插件、配置与导入副本，从空 build 目录执行 `make package-backend`，重新下载构建依赖并完成全部 426 个 Ninja 构建步骤。保留的系统编译器和依赖 sysroot 是构建输入，未复用旧项目目标文件、CMake 缓存或已安装后端。

运行渲染器回归后，通过 `make install` 临时组包并调用正式原子安装器。目标目录原先不存在，安装结果无回滚副本；安装后、首次打开设置前，本插件配置与管理图库均为空。核验安装文件与本次源码一致。

用户再次通过首页引导亲自选择 assets 和壁纸目录，确认首次引导、导入、静态和动态，以及桌面交互正常。真实首次启动为无错误、无渲染进程的静态状态；资源导入后逐文件哈希一致，无旧版迁移记录。

取证时动态开关已关闭，随后进行了短暂的动态复测：约 3.03 秒渲染 45 帧，上限 15 FPS；鼠标输入、视差、粒子及音频处理开启。渲染可执行程序和私有库来自已安装插件，进程映射中没有源码、构建或旧 runtime 的库路径。音频处理开关验证不等于独立的音乐频谱视觉验收。

最终恢复静态，渲染进程退出、15 FPS 保持不变。保留第二轮的已安装修复版本和用户导入图库；原资源独立保留。Forge、顶栏/Dock 相关美化扩展配置与实验前一致。
