# 源码、构建、发行包与安装的边界

2026-10-23，完整包功能分支检查结果。

| 层 | 内容 | 与下一层的关系 |
| --- | --- | --- |
| Git 源码 | C++、GNOME JS/Python、构建/安装工具、文档和上游归属 | 不追踪构建产物、程序包、私人资源或本机 deps |
| build/ | CMake 缓存、二进制、依赖下载和构建记录 | 从指定 checkout 编译；构建缓存不是可搬运的安装物 |
| dist/ | 完整 ZIP、安装器、清单、源码附件及校验和 | 从已有构建复制所需程序和依赖，不安装到当前桌面 |
| GNOME 扩展目录 | 程序、私有库、schema 和许可证 | 完整复制安装，无源码或构建软链接 |
| 用户 data/cache/state | 资源、静态图、缓存、日志和恢复状态 | 与程序目录分离，更新程序不替换资源 |

项目对应源码和依赖对应源码是独立附件，不进入插件安装目录。
安装不需要源码、构建、旧 runtime 或开发者的 deps；仍使用目标系统的 GNOME、图形驱动、Python 等已声明宿主组件。
本机工作区可保留被 Git 忽略的私有工具链链接；干净源码与安装包不携带该链接。

## 验证结果

- Git 不追踪 deps/build/dist/用户资源；源码快照检查拒绝绝对或逃逸的链接。
- 完整 ZIP 不含源码、构建和资源顶层目录，也不含本机工作区绝对路径。
- 已安装插件没有符号链接；实际桌面在前一轮已验证不加载旧 runtime 的程序库。
- 本机构建使用 `make extension` 成功生成完整包。
- 仅将安装器和 ZIP 复制到临时目录，隐藏整个工作区后完成安装；删除临时安装器和 ZIP 后，后端仍通过加载检查。
- 干净 Debian 中暂时移开私有 deps，使用系统库完成“已有构建 → 临时组包 → 隔离安装”；随后隐藏整个 /work，后端加载成功。
- 当前物理桌面的安装清单及 GNOME 设置在检查前后相同；本轮未重装或启用真实桌面插件。

## 本轮修正

- 打包在没有私有 deps 时采用系统 `/usr`；若已有私有配置损坏，则报错而非悄悄替换工具链。
- 拒绝混用其他 checkout 的构建，拒绝未提交的打包输入，核对 C++ 源码树和二进制哈希。
- `make install` 复用完整包安装器；临时组包成功后再进行安装确认，不直接链接源码运行。
- 旧 JS 安装器不能覆盖完整插件，避免产生缺后端的半套安装。
- 默认渲染回归检查能发现 `make package-backend` 的输出。

命令与参数见 [完整包安装说明](FULL-PACKAGE.md)。本轮不更换压缩格式、不裁剪共享库，也不合并或发布。
