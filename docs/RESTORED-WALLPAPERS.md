## 渲染器改动

- 在着色器预处理阶段识别限定特征的旧特效模板：修正音频条多余 `#endif` 和方向变体对只读片元 UV 的写入、Frame Builder 的数值条件，以及旧环形频谱对 float 数组的二级索引和隐式向量截断。没有这些特征的源码保持原样。
- Puppet 的 MDLS 骨骼记录尾部按两个有界 NUL 字符串读取，兼容空字符串旧文件和带 JSON 元数据的新文件。未花加载结果为 982 顶点、54 骨骼、5 动画片段。
- 2D Puppet 的 Y 反射同时修正三角形绕序，保留材质背面剔除语义。
- 无绘制内容的分组也具有脚本属性；场景全部对象创建完成后再执行属性脚本初始化。
- 图层包装对象保持稳定身份；回调绑定自身图层；补全 `getParent()`、`name`、`id` 和非编辑器查询。属性写入同步到渲染数据，字符串使用明确的字符串重载。
- 文本只由共享场景脚本引擎更新，删除文本对象的第二套独立脚本执行。其他图层写入以及初始空文字均可显示，只有内容或像素字号变化才重新栅格化。
- 缺失用户图片或 Windows 快捷方式图标使用透明纹理，避免白色占位块；不会执行 Windows 快捷方式。

## 验证方法

```bash
cmake --build build/portghost --parallel 4
bash renderer/tests/check.sh
python3 renderer/tests/check-scene-scripts.py
bash gnome/tests/check.sh
```

脚本集成测试使用独立 headless GNOME、独立 DBus 和临时目录，验证后创建图层、父分组、稳定身份、自定义属性、跨层赋值、正确回调图层和实际文字像素。需要本机 GNOME、GJS、GdkPixbuf 与已准备的渲染器依赖。

骨骼测试默认使用自建二骨骼合成文件，不包含第三方素材。若在本机解包了未花模型，可额外设置 `PUPPET_TEST_MODEL=/path/to/rw_puppet.mdl`，验证 54 骨骼、5 片段和随时间变化的蒙皮顶点。

真实素材的隔离截图记录在本机 `reports/restored-rendering/`，包含修复前、各阶段诊断和最终输出。高质量静态图仍使用 4K 渲染再缩小到 1080p；日常播放 FPS 设置不变。

## 边界

这不是完整的 Wallpaper Engine API 实现。AveMujica 的原始日期分组还引用了不存在的 `Time` 图层，而实际时钟名为 `Clock`；不能凭名称猜测替换作者引用。日期和星期可独立更新，实际时钟运行自己的脚本；这条原始脚本异常仍会以受限频率记录。Windows 应用启动、缺失的用户自定义图标和未实现的专用脚本接口不在此次渲染兼容范围内。

## 本机验证结果

- C++ 构建、渲染器回归测试、脚本隔离场景和 GNOME 测试套件通过。
- 三张恢复壁纸分别通过普通渲染和 4K→1080p 截图，均无着色器编译错误；未花与酸橙无脚本异常，AveMujica 仅剩上述作者 `Time` 引用问题。
- 《韶华》和《檐花穗影-黍》完成截图回归；黍使用的音频条方向变体也不再编译失败，其原有未实现脚本接口不属于本次验收范围。
- 骨骼测试确认未花蒙皮顶点随时间变化；截图测试不播放系统音频、不移动真实鼠标，因此不将其作为所有音频/鼠标交互已逐项人工验收的证明。
- 部署通过临时文件加原子替换完成，保留旧二进制、旧静态图与 manifest 备份。不覆盖当前会话的 GNOME 模块或 schema。
